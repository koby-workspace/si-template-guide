# 부록 B. 문제 해결과 용어집

## 막혔을 때 순서

1. **오류 메시지를 끝까지 읽습니다.** 영어라도 파일 이름과 줄 번호, 핵심 단어(`is not defined`, `Cannot find module`)는 읽힙니다.
2. **가이드의 마지막 ✏️·📄 블록과 내 파일을 비교합니다.** 이 가이드는 모든 커밋 지점에서 검증했습니다. 대부분 한 줄을 빠뜨렸거나 위치가 다릅니다.
3. **`npm run build`를 돌려 봅니다.** 타입 오류를 파일·줄 단위로 전부 알려 줍니다.
4. **마지막 커밋과 비교합니다.** `Ctrl+Shift+G`(소스 제어)에서 바뀐 파일을 누르면 차이가 나란히 보입니다.
5. 그래도 안 되면 `git stash`로 변경을 잠시 치워 두고, 그 Step을 처음부터 다시 따라 합니다. (`git stash pop`으로 되돌릴 수 있습니다)

## 자주 만나는 문제

### 설치·실행

| 증상                                                  | 원인과 해결                                                                                  |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `npm.ps1 파일을 로드할 수 없습니다`                   | PowerShell 실행 정책. `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` (Part 0)         |
| `'&&' 토큰은 이 버전에서 올바른 문 구분 기호가 아닙니다` | Windows PowerShell 5.1은 `&&`를 모른다. 명령을 한 줄씩 나눈다                               |
| `Port 5173 is in use`                                 | 다른 터미널에서 개발 서버가 이미 돌고 있다. 그 터미널에서 `Ctrl+C`, 또는 다른 포트를 쓴다     |
| 설치한 패키지를 import 하면 빨간 줄                   | `Ctrl+Shift+P` → TypeScript: Restart TS Server                                               |
| 이상한 오류가 계속된다                                | `node_modules` 폴더와 `package-lock.json`이 아니라 **`node_modules`만** 지우고 `npm install`   |

### 모양·포맷

| 증상                                                | 원인과 해결                                                                     |
| --------------------------------------------------- | ------------------------------------------------------------------------------- |
| 저장해도 포맷이 안 된다                             | Prettier 확장 미설치, 또는 `.vscode/settings.json`의 `formatOnSave` 확인        |
| Git이 파일 전체가 바뀌었다고 한다                   | 줄바꿈(CRLF/LF) 차이. 상태 표시줄의 `CRLF`를 눌러 `LF`로 (`.gitattributes`, 1-1) |
| ✏️ "찾을 코드"가 내 파일에서 안 찾아진다            | 저장할 때 Prettier가 줄바꿈 위치를 바꿨을 수 있다. 내용(단어)으로 찾아서 바꾼다 |

### 화면

| 증상                                         | 원인과 해결                                                                           |
| -------------------------------------------- | ------------------------------------------------------------------------------------- |
| 하얀 화면만 나온다                           | F12 → Console의 빨간 오류부터 읽는다. 대부분 import 경로나 오타                       |
| 그리드가 안 보인다 (높이 0)                  | 부모에 높이가 없다. `DataGrid`를 `PageContainer` 안에 넣었는지 (2-7)                  |
| 그리드만 다크 모드가 안 된다                 | `AgGridReact`를 직접 썼다 → `DataGrid` (4-4)                                          |
| 알림·확인 창이 다크 모드를 안 따른다         | `message.success()` 정적 메서드 → `App.useApp()` (3-7)                                |
| 언어를 바꿔도 컬럼 제목이 그대로             | 컴포넌트 밖 상수에서 번역 → `useMemo(…, [t])` (5-4)                                   |
| 탭을 오가면 화면이 초기화된다                | `lazy()`를 렌더 중에 만들었다 / 숨은 탭을 언마운트했다 (6-3, 7-2)                     |
| 화면이 "준비 중"                             | 파일 위치·이름 규칙(`features/*/pages/*Page.tsx`), default export, 메뉴의 `component` |
| 라벨을 누르면 엉뚱한 칸에 커서가 간다        | 폼끼리 입력칸 id가 겹친다 → `Form`에 `name` (9-1)                                     |
| 정렬·컬럼 폭이 자꾸 초기화된다               | 그리드 옵션을 렌더 중 `{{ }}`로 새로 만든다 → 밖의 상수나 `useMemo` (9-7)             |

### 데이터·서버

| 증상                                         | 원인과 해결                                                                                     |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 콘솔에 `[MSW] Mocking enabled.`가 없다       | `.env.development`의 `VITE_USE_MOCK=true`, `public/mockServiceWorker.js` 존재 확인 (3-2)       |
| 요청이 404, 콘솔에 MSW 경고                  | 핸들러 주소와 `httpClient` 주소 규칙이 다르다 → 둘 다 `apiUrl()` / `VITE_API_BASE_URL`         |
| 시드 데이터를 고쳤는데 화면이 그대로         | 시드가 바뀌면 자동 초기화된다(3-3). 그래도 이상하면 개발자 패널 → 가짜 DB 초기화 (13-12)       |
| 저장했는데 목록이 그대로                     | `invalidateQueries` 누락, 또는 queryKey 앞부분이 다르다 (9-2)                                   |
| 같은 조건 [조회]가 서버에 안 간다            | queryKey가 같아서 캐시만 본다 → `SearchForm`의 `onSameSearch={refetch}` (9-1)                   |
| 로그인했는데 이전 사람 데이터가 잠깐 보인다  | 로그인 화면에서 `queryClient.clear()` (8-3)                                                     |
| 권한을 바꿨는데 메뉴·버튼이 그대로           | `["me", "menus"]` 무효화 누락 (10-5)                                                            |
| 알림 토스트가 안 뜬다                        | 15초 주기. 기다리거나 🔔를 열어 본다. 받는 사람의 역할이 규칙 대상인지 확인 (12-5)              |

### TypeScript·ESLint

| 메시지                                                      | 뜻과 해결                                                                                 |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `Property 'xxx' does not exist on type`                     | 타입에 없는 속성. 오타이거나, 유니온 타입을 좁히지 않았다 (`if (menu.type === "PAGE")`)  |
| `Object is possibly 'undefined'`                            | 값이 없을 수 있다. `?.`, `??`, `if`로 확인                                               |
| `React Hook "useXxx" is called conditionally`               | 훅을 `if` 아래나 안에서 불렀다. 훅은 컴포넌트 맨 위에서 모두 부른다                      |
| `React Hook "useXxx" is called in function "..."`           | `use`로 시작하는 이름은 훅으로 간주된다. 일반 함수·변수 이름을 바꾼다 (9-5)              |
| `React Hook useEffect has a missing dependency`             | Effect 안에서 쓰는 값을 의존성 배열에 넣는다                                             |
| `Fast refresh only works when a file only exports components` | 컴포넌트 파일에서 상수·함수도 내보냈다 → 파일을 나눈다 (6-2)                           |
| `'xxx' is defined but never used`                           | 안 쓰는 변수·import. 지운다                                                              |

## 용어집

| 용어                       | 뜻                                                                                              |
| -------------------------- | ----------------------------------------------------------------------------------------------- |
| SPA                        | Single Page Application. HTML이 하나이고, 주소가 바뀌어도 자바스크립트가 화면을 바꾼다          |
| MDI                        | Multiple Document Interface. 한 화면 안에서 여러 업무 화면을 탭으로 동시에 여는 방식            |
| keep-alive                 | 화면을 숨겨도 없애지 않고 상태를 유지하는 것                                                    |
| 번들러                     | 수많은 소스 파일을 브라우저용 파일로 묶어 주는 도구 (Vite)                                       |
| HMR                        | 저장하면 새로고침 없이 바뀐 부분만 반영되는 기능                                                |
| 컴포넌트 / props / state   | 화면 조각 함수 / 그 함수의 매개변수 / 바뀌면 화면을 다시 그리게 하는 값                          |
| 훅 (Hook)                  | `use`로 시작하는 함수. 컴포넌트에 기능을 끼워 넣는다                                            |
| Context                    | props를 일일이 넘기지 않고 아래쪽 어디서든 꺼내 쓰는 값                                          |
| Effect                     | 렌더링 밖 세상(브라우저 API, 타이머, 이벤트)과 동기화하는 코드 (`useEffect`)                    |
| 불변 업데이트              | 객체·배열을 고치지 않고 새로 만든다. React가 변화를 알아챈다                                    |
| 파생 상태                  | 저장하지 않고 다른 값에서 계산하는 값 (활성 탭 = 주소에서 계산)                                 |
| 단일 진실 공급원           | 같은 정보를 두 곳에 두지 않는다                                                                 |
| 서버 상태                  | 원본이 서버에 있는 데이터. 화면의 것은 복사본(캐시)                                             |
| queryKey                   | TanStack Query가 캐시를 구별하는 이름표. 조건이 바뀌면 키가 바뀌고 자동으로 다시 조회한다       |
| 캐시 무효화 (invalidate)   | "이 데이터는 낡았다" 표시. 그 데이터를 보는 화면이 알아서 다시 조회한다                         |
| 폴링                       | 일정 주기로 서버에 물어보는 것 (알림 15초)                                                      |
| MSW / Service Worker       | 브라우저에서 요청을 가로채 가짜 응답을 주는 도구 / 브라우저와 네트워크 사이의 중간 관리자 스크립트 |
| 시드 데이터                | 가짜 DB의 초기 데이터                                                                           |
| Problem Details            | HTTP API 오류 응답 표준 형식 (RFC 9457, Spring `ProblemDetail`)                                 |
| 디자인 토큰                | 색·모서리·크기 같은 디자인 값에 붙인 이름 (`colorPrimary`)                                      |
| 알고리즘 (antd)            | 토큰을 받아 다크·촘촘함 등으로 변환하는 함수                                                    |
| FOUC                       | 스타일 적용 전 화면이 잠깐 보이는 깜빡임                                                        |
| 로케일                     | 언어 + 지역 형식 (`ko-KR`, `en-US`)                                                             |
| 네임스페이스 (i18n)        | 번역 파일을 나눈 단위 (`common`, `users`)                                                       |
| 구별된 유니온              | `type` 같은 필드 값에 따라 나머지 필드가 달라지는 타입                                          |
| 제네릭                     | 타입을 매개변수처럼 넘기는 것 (`DataGrid<User>`)                                                |
| 화면 레지스트리            | 화면 파일 목록. 메뉴의 `component` 값으로 실제 화면을 찾는다                                    |
| 코드 분할                  | 앱 JS를 화면별로 쪼개서 필요할 때 내려받는 것 (`lazy`, 동적 `import()`)                         |
| Error Boundary             | 하위 컴포넌트의 렌더링 오류를 잡아 대체 화면을 보여 주는 컴포넌트                               |
| 인증 / 인가                | 누구인가(로그인) / 무엇을 할 수 있나(권한)                                                      |
| RBAC                       | 역할 기반 권한. 사람 → 역할 → 메뉴 × 동작                                                       |
| XSS                        | 악성 스크립트를 화면에 심는 공격. HTML을 그리기 전에 소독(sanitize)해서 막는다                  |
| CORS / 프록시              | 다른 출처 요청을 막는 브라우저 규칙 / 같은 출처로 받아 대신 전달하는 서버                        |
| SPA fallback               | 없는 경로에도 `index.html`을 주는 웹 서버 설정. 없으면 새로고침 시 404                          |
| 멱등                       | 여러 번 해도 결과가 같은 것 (읽음 처리)                                                         |
| 순수 함수                  | 같은 입력이면 같은 결과, 바깥에 영향이 없는 함수                                                |
